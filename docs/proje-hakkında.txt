# SıraSende – Güncel MVP Sprint Planı

## 1. Proje Özeti

**SıraSende**, müşterilerin üyelik oluşturmadan işletmelerden randevu almasını, işletme sahibinin ise giriş yaparak gelen randevuları yönetmesini sağlayan mobil öncelikli bir randevu uygulamasıdır.

Proje yaklaşık **2,5 haftalık geliştirme süresi** içerisinde tamamlanacaktır.

Ana hedefler:

* Flutter ile Android ve iOS uyumlu mobil uygulama geliştirmek
* FastAPI ile ortak ve bağımsız REST API oluşturmak
* PostgreSQL ile randevu ve işletme verilerini yönetmek
* Aynı saat için birden fazla randevu oluşmasını engellemek
* İşletme sahibinin randevuları onaylayabilmesini sağlamak
* Vakit kalırsa Google Calendar entegrasyonu ve web arayüzü eklemek

# 3. Platform Hedefleri

Mobil uygulama Flutter ile geliştirileceği için ortak kod tabanı:

* Android
* iOS

platformlarında çalışacak şekilde hazırlanacaktır.

Ana geliştirme ve test işlemleri Android üzerinde yapılacaktır.

iOS uygulaması için:

* Flutter kodları iOS uyumlu yazılacak
* iOS klasörü korunacak
* Platforma özel paketler dikkatli seçilecek
* Son iOS derleme ve test işlemi için macOS ve Xcode gerekebilecektir

Web tarafı için backend baştan bağımsız REST API olarak tasarlanacaktır. Bu nedenle mobil tamamlandıktan sonra React web arayüzü aynı API’yi kullanabilecektir.

# 14. Pull Request Akışı

Her görev için:

1. GitHub Issue oluşturulur.
2. `develop` dalından yeni branch açılır.
3. Kod yazılır.
4. Test edilir.
5. Küçük ve anlamlı commit’ler atılır.
6. Branch GitHub’a gönderilir.
7. `develop` dalına pull request açılır.

# 17. Kritik İş Kuralları

## Slot Süresi

İşletme yalnızca şu slot sürelerinden birini kullanabilir:

```text
30 dakika
45 dakika
60 dakika
```

## Geçmiş Randevu

* Geçmiş tarihe randevu alınamaz.
* Bugünün geçmiş saatleri seçilemez.

## Aktif Randevu

Aşağıdaki durumlar slotu dolu sayar:

```text
pending
confirmed
```

Aşağıdaki durumlar slotu boş bırakır:

```text
cancelled
completed
```

## Çakışma Kontrolü

Aynı:

* İşletme
* Tarih
* Başlangıç saati

için ikinci aktif randevu oluşturulamaz.

Backend yalnızca uygulama kontrolüne güvenmeyecektir. PostgreSQL üzerinde aktif randevular için benzersizlik kuralı bulunacaktır.

## Randevu Durumları

```text
pending
confirmed
cancelled
completed
```

Varsayılan yeni randevu durumu:

```text
pending
```
